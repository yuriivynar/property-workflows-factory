## Research findings
- **Role:** `src/lib/auth/require-role.ts:24` rejects any role other than manager or admin. `AppRole` already includes `"vendor"`, and the `profiles_role_check` constraint already allows it (`20261029090000_vendor_role.sql`). The role check is the only blocker in the TypeScript auth layer.
- **List page:** `src/app/runs/page.tsx` reads `run_overview` for everyone. It shows the template name, a "Launch a template" button, and `formatProgress`. It never looks at the role.
- **RLS exposure:** the `runs` policy (`20261020115705_workflow_runs.sql:~123-127`) lets any task assignee see the run. A vendor who used `run_overview` would therefore see the template name, which AC-VENDOR-12 forbids. The vendor branch must use only `vendor_runs()`.
- **Marking tasks:** `mark_task_done` already lets the assignee mark their own task (`20261020120848_run_progress.sql:34`). The tests call the later two-argument version (`20261021085138`). AC-VENDOR-05 and AC-VENDOR-16 should need no new SQL beyond `vendor_runs()`. I did not check that a completed run stays `completed` after a late mark. `tests/db/vendor-list.test.ts` covers it, so run it first.
- **Existing helpers:**
  - `runsListState` and `formatProgress` in `src/lib/runs/domain.ts` are the models for the new helpers.
  - `MESSAGES` and `LABELS` live in `src/lib/runs/messages.ts`.
  - `EmptyState` in `@/components/ui` takes `actionHref` and `actionLabel`, and I haven't checked whether they are optional. The vendor empty state has no action, so use plain text or `Notice` if they are required.
- **Latest migration:** `20261029090000_vendor_role.sql`. The new file needs a later timestamp.
- **Tests (read-only):** `tests/db/vendor-list.test.ts`, `src/lib/runs/vendor-list.test.ts` and `src/lib/auth/current-user-vendor.test.ts`.

## Design
1. **Database:** one new migration, `supabase/migrations/20261030000000_vendor_runs.sql`.
   - `private.vendor_runs()` is `security definer` with `set search_path = ''`.
     - It returns `table(id uuid, case_name text, status text, your_done integer, your_total integer)`.
     - It selects from `public.runs` joined to `public.run_tasks` on `assignee_id = (select auth.uid())`.
     - It groups by run, with `your_done = count(*) filter (where status = 'done')::int` and `your_total = count(*)::int`.
     - It orders by `created_at desc, id`.
     - It returns no rows when `auth.uid()` is null. It does not need a role check, because "assignee of a task" is the access rule.
   - Grants: `revoke execute ... from public, anon` and `grant execute ... to authenticated`.
   - `public.vendor_runs()` is a `security invoker` wrapper with the same signature and the same revoke and grant.
   - Do not select the template, version or manager columns.
2. **Domain and messages:**
   - Add `formatYourTasks(done, total)`, which returns `Your tasks: ${done} of ${total} done`.
   - Add `vendorRunsListState(rows)`, which returns `"empty"` for null or `[]` and `"table"` otherwise.
   - Add `MESSAGES.noTasksAssigned = "No tasks assigned to you yet."`.
   - Add a `LABELS.columnYourTasks` label only if the table needs a header.
3. **Auth:** in `currentUser`, accept `role === "vendor"` as well. `requireAdmin` stays unchanged and still refuses vendors.
4. **Page:** in `RunsPage`, call `currentUser(supabase)` after the sign-in redirect.
   - For a vendor:
     - Call `supabase.rpc("vendor_runs")`.
     - Render a table with the case name (a `TextLink` to `/runs/[id]`), a `StatusBadge`, and `formatYourTasks`. There is no template column and no launch button.
     - If the state is `"empty"`, show only `MESSAGES.noTasksAssigned`, with no table.
   - For managers and admins: keep the current code path unchanged.
   - Regenerate or hand-edit `database.types.ts` for the new function, if the project keeps that file under version control.

## Risks
- **Template leak:** if the vendor branch falls back to `run_overview`, the template name becomes visible. Keep the branches separate and make the vendor query only `vendor_runs()`.
- **Column set:** the test requires exactly five columns, so adding one (for example `created_at` for ordering) breaks AC-VENDOR-12. Order inside the function instead.
- **Integer casts:** `count` returns bigint. Cast to `int`, or `your_done` and `your_total` arrive as strings.
- **Empty state:** the shared `EmptyState` may force a launch action. Check its props before using it, because vendors must not see "Launch a template".
- **Unknown roles:** `currentUser` must still return `NOT_ALLOWED` for any other role, and `requireAdmin` must stay admin-only.
- **Migration order:** the timestamp must be later than `20261029090000`, and the existing migrations must not be edited.
- **Run page for vendors:** `/runs/[id]` may show the template or the manager to a vendor. That is outside this slice and not in the listed criteria. Flag it for the next slice.
- **Protected files:** tests, `docs/conformance.md`, `requirements/` and `openspec/` are off limits.
